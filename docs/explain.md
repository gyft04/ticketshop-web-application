Was wäre wenn JS nicht nur im Browser laufen würde, sondern auch auf dem Server? Das war die Frage, die Ryan Dahl 2009 dazu brachte, Node.js zu entwickeln. Node.js ist eine JS-Laufzeitumgebung, die es ermöglicht, JS außerhalb des Browsers auszuführen. Es basiert auf der V8-JS-Engine von Google Chrome und bietet eine Vielzahl von Modulen, die es Entwicklern ermöglichen, serverseitige Anwendungen zu erstellen.
Node.js ist besonders beliebt für die Entwicklung von Webanwendungen, APIs und Echtzeitanwendungen. Es verwendet ein ereignisgesteuertes, nicht blockierendes I/O-Modell, das es ermöglicht, viele Verbindungen gleichzeitig zu verarbeiten, ohne dass die Leistung beeinträchtigt wird. Dies macht Node.js ideal für Anwendungen, die eine hohe Skalierbarkeit erfordern.
Laufzeitumgebung bedeutet: Im Browser läuft JavaScript in einer Browser-Umgebung, die Zugriff auf DOM, BOM und andere browser-spezifische APIs bietet. Mit Node.js läuft JS auf dem Computer des Entwicklers oder auf einem Server, und es bietet Zugriff auf das Dateisystem, Netzwerkanfragen und andere serverseitige Funktionen. Das bedeutet, dass Entwickler mit Node.js nicht nur Webanwendungen erstellen können, sondern auch Skripte, Tools und sogar Desktop-Anwendungen entwickeln können.
package.json ist eine Datei, die in Node.js-Projekten verwendet wird, um Informationen über das Projekt und seine Abhängigkeiten zu speichern. Sie enthält Metadaten wie den Namen des Projekts, die Version, die Beschreibung und die Hauptdatei. Außerdem listet sie die Abhängigkeiten auf, die das Projekt benötigt, um ordnungsgemäß zu funktionieren. Diese Abhängigkeiten können mit dem Node Package Manager (npm) installiert werden, was die Verwaltung von Bibliotheken und Modulen erleichtert.
node_modules ist ein Ordner, der automatisch erstellt wird, wenn npm Pakete installiert werden. Er enthält alle installierten Pakete und deren Abhängigkeiten. Wenn ein Entwickler ein Paket mit npm installiert, wird es in diesem Ordner abgelegt, damit es von der Anwendung verwendet werden kann. Es ist wichtig zu beachten, dass der node_modules-Ordner oft sehr groß werden kann, da er alle Abhängigkeiten enthält, einschließlich derjenigen, die von anderen Paketen benötigt werden. Daher wird empfohlen, diesen Ordner nicht in Versionskontrollsysteme wie Git aufzunehmen.
package-lock.json ist eine Datei, die automatisch von npm generiert wird, wenn Pakete installiert oder aktualisiert werden. Sie merkt sich die genaue Version der installierten Pakete und deren Abhängigkeiten. Dies ist wichtig, um sicherzustellen, dass alle Entwickler, die an einem Projekt arbeiten, die gleichen Versionen der Pakete verwenden, was die Konsistenz und Stabilität des Projekts gewährleistet. Wenn jemand anderes das Projekt klont und npm install ausführt, wird die package-lock.json-Datei verwendet, um die genauen Versionen der Pakete zu installieren, die in der ursprünglichen Installation verwendet wurden.
nodemon ist ein Tool, das die Entwicklung von Node.js-Anwendungen erleichtert, indem es automatisch den Server neu startet, wenn Änderungen an den Dateien vorgenommen werden. Man benutzt es so: nodemon app.js. oder npx nodemon app.js. npx ist ein Tool, das mit npm geliefert wird und es ermöglicht, Pakete auszuführen, ohne sie global installieren zu müssen. Es sucht nach dem angegebenen Paket in den lokalen node_modules und führt es aus, wenn es gefunden wird. Wenn das Paket nicht lokal installiert ist, sucht npx in der globalen Installation und führt es von dort aus. Dies ist besonders nützlich für Tools wie nodemon, die häufig in Projekten verwendet werden, da es die Notwendigkeit beseitigt, sie global zu installieren.
git remote add origin <repository-url> ist ein Befehl, der verwendet wird, um ein Remote-Repository zu einem lokalen Git-Repository hinzuzufügen. Dabei ist <repository-url> die URL des Remote-Repositorys, das hinzugefügt werden soll. Dieser Befehl ermöglicht es Entwicklern, Änderungen von ihrem lokalen Repository zu einem entfernten Repository zu pushen oder von diesem zu pullen. Es ist ein wichtiger Schritt, um die Zusammenarbeit in einem Team zu ermöglichen und den Code auf Plattformen wie GitHub oder GitLab zu hosten.
git push -u origin main ist ein Befehl, der verwendet wird, um Änderungen von einem lokalen Git-Repository zu einem Remote-Repository zu übertragen. Dabei ist origin der Name des Remote-Repositorys und main der Name des Branches, auf den die Änderungen gepusht werden sollen. Das -u-Flag steht für "upstream" und bedeutet, dass der lokale Branch main mit dem Remote-Branch main verknüpft wird. Dadurch wird es einfacher, zukünftige Änderungen zu pushen oder zu pullen, da Git weiß, welcher Remote-Branch mit dem lokalen Branch verbunden ist.
